## 1. 원문과 번역에 대하여

원문은 Karpathy의 gist 글이라 전문을 옮겨 적거나 전체 번역본을 싣지 않았습니다. 대신 원문의 구성과 핵심 주장을 요약해 두었습니다. 자세한 문장은 위 링크에서 직접 읽어 보시길 권합니다.

### 원문 구성 (요지)

1. **핵심 아이디어:** RAG와 비교했을 때, 위키가 지식을 누적한다는 점
2. **아키텍처:** 세 계층
   - 원본 자료: 변경하지 않는 진실의 원천
   - 위키: LLM이 작성하고 관리하는 마크다운 페이지
   - 스키마: LLM이 따를 작업 규칙 문서 (예: CLAUDE.md)
3. **작업(Operations):** Ingest(자료 추가), Query(질의응답), Lint(상태 점검)
4. **색인과 기록:** `index.md`(목록), `log.md`(작업 기록)
5. **선택적 도구:** 규모가 커졌을 때 쓰는 검색 도구
6. **실용 팁:** 웹 클리퍼, 로컬 이미지 저장, Obsidian 그래프 뷰, Git 버전 관리 등
7. **왜 작동하는가:** 사람이 위키를 버리는 이유는 유지보수 부담이며, LLM이 그 부담을 거의 없앤다는 논지
8. **유의점:** 구체적 구현이 아닌 추상적 아이디어 문서

## 2. 한글 번역 요약

- 기존 RAG는 질문할 때마다 원본 문서에서 조각을 찾아 답을 만듭니다. 그래서 지식이 쌓이지 않습니다.
- 이 패턴에서는 LLM이 자료를 추가할 때마다 위키를 만들고 갱신합니다. 요약, 개체 페이지, 상호 링크, 모순 표시를 미리 정리해 둡니다.
- 사용자는 자료를 고르고 질문합니다. 위키 작성과 관리는 LLM이 맡습니다.
- 좋은 답변도 다시 위키에 저장할 수 있어서, 질문이 쌓일수록 위키가 자랍니다.

## 3. 컨셉 해설

### RAG와 위키의 차이

RAG는 "질문할 때 찾아서 답하기"입니다. 같은 질문을 반복하면 매번 원본을 처음부터 다시 뒤집니다. 위키는 "넣을 때 정리해 두기"입니다. 자료가 들어오는 시점에 LLM이 기존 페이지와 연결하고 충돌을 표시해 둡니다. 그래서 두 번째 질문부터는 이미 정리된 지식을 바로 씁니다.

### 세 계층이 주는 것

- **원본 자료**는 바꾸지 않습니다. 위키가 틀려도 원본으로 되돌아갈 수 있습니다.
- **위키**는 LLM의 몫입니다. 사람이 직접 쓰지 않아도 되므로 유지 비용이 낮습니다.
- **스키마**는 LLM의 작업 규칙입니다. 같은 규칙을 따르면 페이지 구조가 일관되게 유지됩니다.

### Lint가 중요한 이유

지식 베이스는 시간이 지나면 낡습니다. 새 자료가 옛 주장과 충돌하거나, 어디서도 링크되지 않는 고아 페이지가 생깁니다. Lint 작업은 이런 상태를 주기적으로 점검합니다. 사람이 하기 가장 귀찮은 일을 LLM이 맡는 셈입니다.

### 사람이 위키를 버리는 이유

위키가 실패하는 이유는 대부분 내용이 틀려서가 아니라 관리가 귀찮아서입니다. 링크를 고치고, 요약을 갱신하고, 모순을 찾는 일은 꾸준히 해야 합니다. 이 패턴은 그 일을 LLM에게 넘깁니다. 사람은 무엇을 읽고 무엇을 물을지만 정하면 됩니다.
